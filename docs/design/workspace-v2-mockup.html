Kept from draft 1

  • Layout: list on the left, detail on the right, resizable divider.
  • Top bar: target URL, Recording, Stop, Clear, Export menu, New session.
  • Session strip: App connected, Browser + Server, Masking off, Local session.
  • Filters: search, type, source, method and domain dropdowns, plus the count.
  • Detail tabs: Overview, Headers, Request, Response, Timing.
  • Body viewer: Tree, Pretty and Raw, Copy body with its menu, Save, Find in response with a match count, Expand all and Collapse all.
  • Value tools: click a value to get its path as a breadcrumb, then Copy value or Copy path.

Added, from the repo

  • Status filter for 2xx to 5xx, Failed and Pending, and a Bodies toggle for body search. Both already exist in core/filter.ts.UI-02
  • Domain and Size columns are back, as in RequestTable.tsx. Size shows a short reason when the body is missing.
  • Linked calls in the list and in Overview: Server calls, Triggered by, or Not linked, matched on trace ID only.COR-01
  • Request tab now uses the same viewer as Response, with query params and body.
  • Cookies are split out of the cookie and set-cookie headers. Every header row can be copied, and so can each whole group.UI-03
  • Copy as cURL and fetch in one request-level Copy menu.DX-01
  • Save one request as a body file or a HAR entry. You can also select rows and export or copy just those.
  • Export dialog lets you pick the whole session or the filtered view, and shows the masking warning.EXP-01
  • Group by page uses navigationId. It is off by default, so the flat list stays.UI-04
  • Missing bodies say why: truncated, binary, redirect, too large or a failed read.US-06

Left out on purpose

  • Type and mock generation (TypeScript, Zod, MSW). They are not in the PRD. They would make the app a code generator instead of an inspector.
  • Insights panel. Duplicate detection is Phase 3. Add it once pilot data shows people want it.
  • Compare and replay. These are DX-02 and MOCK-01, also Phase 3. They need persistence first, which is SQLite in Sprint 4.
  • Toggling masking mid-session. Redaction runs before values reach the renderer, so masking is chosen when a session starts. The strip shows the setting but you can't change it there.
  • Waterfall column. Timing stays in the Timing tab until UI-04 is scheduled.

Things to try in the frame

  2. On the products response, type fan in Find, then click a value and use Copy path.
  3. Open the POST to /cart/items and look at the Request tab with its JSON body.
  4. Open the failed analytics call, the redirect and the image to see the missing-body states.
  5. Tick a few rows and export the selection, or open Export in the top bar.
